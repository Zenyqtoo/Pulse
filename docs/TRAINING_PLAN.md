# Локальная модель: этап 1 — данные (02.11.2026)

## Что подготовлено

`backend/scripts/prepare_training.py` создаёт набор для слепой ручной разметки из обезличенного публичного снимка, без подключения к рабочей базе. Синтетические и личные сообщения исключаются. Ответы rules-v1/LLM не показываются и не становятся эталонными метками.

```powershell
# Из Pulse/backend, существующим Python .venv
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_training.py --output ../../work/pulse-study/training-v1
```

Каталог назначения должен быть пустым: повторная генерация не затирает разметку. Для новой версии используйте другой каталог. `blind.jsonl` — тексты и пустые поля; `manifest.json` — разбиение и статистика; `annotate.html` — автономная форма, без отправки данных наружу. Форму можно открыть в браузере. Она хранит черновик в localStorage, если браузер это разрешает, и позволяет скачать/импортировать JSON разметки. Скачивайте резервную копию регулярно.

Train/dev/test распределяются по группам приблизительно 70/15/15. Совпадающий текст, явные duplicate_of, общий URL статьи/родителя и близкие перепечатки с Jaccard ≥0.8 по словесным 4-граммам объединяются транзитивно. Это уменьшает очевидные утечки; парафразы и общие события ещё требуют ручного контроля. При расширении набора сохраните замороженный test и проверьте пересечения с новыми обучающими текстами. Нельзя просто заново перемешать набор после получения результатов.

Это отдельный набор для обучения модели. Старое правило test/dev из `evaluation.py` для GoldLabel не изменено: автоматически смешивать два разбиения нельзя.

## Инструкция разметчику

Читайте текст и контекст, не смотрите результат анализа приложения. Выберите все шесть полей, укажите свой код; трудные случаи можно пропустить и обсудить отдельно.

- **География:** local — именно город Павлодар; not_local — другой город или только область; possible — данных недостаточно. «Холодные батареи» без контекста не доказывает город. При нескольких городах уточните основной предмет сообщения и оставьте заметку, если однозначного ответа нет.
- **Подразделение:** одно основное из справочника; not_applicable для сообщений вне задач служб; other — городская тема, не попавшая в профильные категории. Содержимое новости может относиться к подразделению, даже если это не обращение.
- **Тональность:** отношение, выраженное автором, а не негативность события. Нейтральная новость об аварии не обязана быть negative. Ирония/смешанные оценки — повод для заметки и обсуждения.
- **Тип:** жалоба, вопрос, предложение, благодарность, информация, реклама/спам.
- **Кто пишет:** пользовательское обращение/комментарий, редакция/СМИ, официальная организация, неизвестно. Тип канала сам по себе не подтверждает официальность; учитывайте контекст. Пользовательский комментарий не удостоверяет проживание автора в городе.
- **Язык:** русский, казахский, смешанный, другой.

Разметка не заполняется из предсказаний или автоперевода правил. Поле label_origin=human означает заявление разметчика о ручном выборе, а не независимое техническое доказательство. Для итогового test назначьте человека, который не видел предсказаний; спорные случаи желательно проверить вторым разметчиком. Его ответы не использовать для подбора правил, промпта, порогов и обучения.

Проверка скачанной разметки:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_training.py --output ../../work/pulse-study/training-v1 --validate ПУТЬ-К-РАЗМЕТКЕ.json
```

Валидатор проверяет ID, допустимые значения, полноту, код разметчика и происхождение меток. Существующую базу не меняет.

## Пробелы данных перед обучением

Текущий снимок: 391 реальная запись, из них только 25 комментариев/ответов; остальные — статьи и публикации. Есть устаревшие записи, спам и другие города — они полезны как отрицательные примеры, но выборка нерепрезентативна.

Нужно дополнить реальными пользовательскими сообщениями о разных городских темах, казахскими/смешанными текстами и неоднозначными географическими примерами. Не создавать вымышленные обращения под видом реальных. Пока ручной разметки нет, обученная модель и целевая точность не заявляются. Предсказания правил допустимы только как отдельно обозначенная слабая разметка обучающей части, не как независимый test.

## Следующие этапы

1. Разметить и проверить выборку; зафиксировать независимый test.
2. Сравнить текущие правила с простым локальным классификатором; затем оценить дообучение открытой многоязычной модели на train, подбор параметров на dev.
3. Проверить precision/recall географии (особенно пропуски нужных сообщений), macro-F1 и accuracy подразделений/тональности, результаты RU/KK и отдельно комментариев/СМИ. Указать объём каждой подвыборки.
4. Встроить модель с версией, локальным инференсом и очередью неуверенных результатов. Softmax/score не объявлять достоверной вероятностью без проверки калибровки.
5. Экспортировать подтверждённые исправления сотрудников только в обучающий пул, исключая замороженный test и связанные с ним группы. Новую модель проверять до замены работающей.

## Первый прототип: выбранный подход

Пользователь поручил выбрать способ разметки самостоятельно. Выбран bootstrap: отдельные метки rules-v1 только для train; dev/test остаются без подсказок. Канонический подготовленный каталог: `work/pulse-study/training-v3` в родительской папке хакатона. Содержит 260 train / 64 dev / 67 test. Форма, открытая на localhost:8010, использует идентичные ID и слепые тексты из training-v2; скачанная разметка совместима с v3.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_training.py --output ../../work/pulse-study/training-НОВАЯ-ВЕРСИЯ --weak-train
```

`scripts/train_local_model.py` обучает четыре линейных классификатора на признаках открытого `intfloat/multilingual-e5-small`: подразделение, тональность, тип, география. Основа frozen — её веса НЕ дообучаются. Метки пока слабые, от правил. Поэтому корректная формулировка: «адаптация открытого кодировщика обученными классификаторами», не «мы дообучили BERT на ручной городской разметке». Поддержка многоязычной основы не доказывает качество на казахском.

Установка проводится в отдельное окружение `.runtime/ml-venv` (вне репозитория); рабочее `.venv` приложения не меняется. Зависимость для прототипа: sentence-transformers==6.2.0. Команда обучения из корня хакатона после установки:

```powershell
.\.runtime\ml-venv\Scripts\python.exe -X utf8 Pulse/backend/scripts/train_local_model.py --dataset work/pulse-study/training-v3 --output .runtime/local-model-v1 --cache .runtime/hf-cache
```

Скрипт не читает метки dev/test, не считает независимую точность, не включает модель в работающий backend. Сохраняет линейные веса в JSON и model_card.json с происхождением меток, версиями и ограничениями. При единственном классе задача явно помечается как constant; такой результат не считать уверенным содержательным предсказанием. Значения score некалиброваны.

Код генерации/линейных голов проверен тестами без скачивания модели. Фактическое завершение обучения проверять по артефактам и журналу запуска, а не по наличию скрипта или этой инструкции.

Фактический результат 02.11.2026: прототип обучен, `heads.json` и `model_card.json` созданы в `.runtime/local-model-v1` родительской папки. Инференс с отключённым HF Hub выполнен на трёх технических примерах; благодарность за автобус ошибочно классифицирована как neutral/info. Это проверка работоспособности, не независимая метрика. Полный backend-прогон: 89 passed. В работающее приложение прототип не включён. Подробный статус и оставшиеся задачи: `work/pulse-study/ML_PROGRESS.md`.
