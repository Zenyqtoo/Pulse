# Проверка City Alert для жюри

Актуально на 02.11.2026. Репозиторий содержит код, обезличенные публичные данные и отдельно помеченный учебный набор. Решение принимает сотрудник; аналитика системы помогает проверить проблему.

## Запуск и данные

Используйте команды из [README](../README.md). После запуска на новой пустой базе:

```bash
docker compose exec app python -m app.cli load-snapshot
```

Снимок: **396 реальных записей + 104 учебных**, 46 сохранённых групп, включая неактивные и три редакторские подборки. Реальные источники: три Telegram-канала, два RSS, комментарии pavon.kz, статьи gorodpavlodar.kz и obozrenie.kz — восемь источников. Новые статьи не считаются новыми сообщениями жителей. Даты сохранены, в том числе архив 2024–2025 годов.

Личные обращения, пользователи, пароли, конфигурации подключений и токены в снимок не входят. Коллекторы после импорта выключены. Для учебного Direct отдельно выполните `load-demo`. Рабочую базу не очищайте ради повторного импорта.

## Что проверить по ТЗ

| Проверка | Где смотреть | Граница результата |
|---|---|---|
| Единая лента из нескольких источников | Лента → источник, платформа, происхождение | Реальные и учебные записи разделены |
| Подразделение, тональность, уверенность | Открыть сообщение и его анализ | Без ключа Claude работает rules-v1; независимая точность 80%/75% не подтверждена |
| География и контекст | Детали комментария, очередь уточнения места | Городской источник не доказывает, что каждая запись о Павлодаре |
| Кластеры и приоритет | Главная и «Все проблемы» | Автоматический приоритет требует проверки сотрудником |
| Поддержка решения | «Подготовить данные для решения» | Метрики по записям, цитаты, источники, пробелы; без автоматического решения за акимат |
| Разделение СМИ и пользователей | Фильтр «Кто пишет», карточка решения | 25 реальных комментариев; аккаунты не равны людям |
| Аналитика и экспорт | Аналитика, подразделения, экспорт | Дашборды следующих этапов ТЗ ещё не завершены |
| Обработка и контроль | Оператор: статус и комментарий; администратор: аудит | Закрытие само по себе не означает подтверждение всеми жителями |
| Права и приватность | Сравнить admin/operator/viewer | Viewer не получает Direct; маскирование не гарантирует распознавание любого имени |

## Демо на 3 минуты

1. **Сценарии для защиты**: показать три подборки и даты. Это редакторский отбор существующих записей, а не три автоматически выявленные текущие массовые аварии.
2. **Аллергенные сорняки**: открыть карточку и реальный комментарий; рядом отдельная публикация СМИ. Общий адрес и единый очаг не установлены.
3. **Отопление**: назвать архивную дату 07.10.2025. Количество жалоб в статье не выдавать за число собственных сообщений системы.
4. **Обычная проблема на главной**: показать доказательства, подразделение, пробелы и смену статуса под оператором. Учебный набор явно обозначить, если показываете его.
5. **Аналитика и роли**: показать фильтры, экспорт и ограничение Direct для viewer.

## Проверка сборки

107 backend-тестов прошли на отдельной временной SQLite-базе, frontend собран. Браузером проверены `/defense` и открытие DecisionDrawer. Тесты парсеров используют фиксированные примеры и имитации внешних запросов: они не гарантируют доступность сайтов завтра и не измеряют точность на независимых реальных данных.

## Что не заявлять на защите

- Полное выполнение всех пунктов ТЗ и подтверждённую точность 80%/75%.
- Живое подключение Instagram/Threads, Telethon и официального Direct: они требуют настройки и авторизации владельца.
- Использование экспериментальной локальной модели в основном сайте: она сохранена для будущего и выключена.
- Независимость перепечаток, установленную личность авторов или массовость по одному комментарию.
- Постоянный автоматический сбор в локальном демо: расписание выключено, доступен ручной запуск.

Docker/PostgreSQL и размещение в Казахстане в этой среде не проверялись. Подробности: [подборки](DEFENSE_CASES.md), [источники](SOURCES.md), [модель](OPTIONAL_LOCAL_MODEL.md).
